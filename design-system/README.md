# Design System（设计系统）

内部合同工作台的统一视觉语言。目标：任何 agent 产出的界面与人工产出的界面看起来是同一套系统，而不是一套库默认样式。

## tokens/
设计令牌（颜色/字号/间距/圆角，机器可读 JSON 优先）。合同系统偏"数据密集 + 状态清晰"，令牌服务两类需求：金额/日期数字可读、合同状态一眼可辨。见 `tokens/README.md` 的真实令牌集合。

## components/
组件约定（每个组件：用途、变体、禁用场景）。优先沉淀被复用过的：
- 合同列表行（含状态徽章 + 金额 + 到期日）
- 合同详情头（相对方 / 金额 / 状态 / 版本）
- 状态机流转条（起草→…→归档的可视化）
- 收付款/里程碑表格
- 表单（金额输入走"分"校验、日期选择）
- 空状态（无合同 / 无里程碑）
- 错误/加载反馈

## patterns/
交互模式（表单、反馈、加载、空状态——沉淀复用过的模式）：
- 金额输入校验（整数"分"、非法字符即错）
- 只读/冻结态表达（生效后字段不可点的样式 + 提示）
- 变更单差异展示（父版本 vs 新版本字段 diff）
- 越权操作反馈（非 admin 点击敏感字段时的明确拒绝）
- 列表筛选与关键词搜索（按相对方/状态/金额区间）
- 日期相对化（"今日到期""逾期 5 天"）
