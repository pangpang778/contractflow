# T6 前端两域接线 + 集成冒烟（seam S4 · F-0005 收敛接线票）· ready-for-agent（C3 预授权）

`blockedBy: [02-counterparty-http-api, 04-amendment-http-api-apply, 05-contract-list-form-counterparty]` — 两域 API 与合同面就绪后接线；全部阻塞满足即最后 frontier 项，收敛两域到同一前端面。
目标：把变更单 UI + 相对方管理 UI 挂到真实 API，并完成跨切片接线冒烟（F-0005：无单片独有的挂载/冒烟交给本集成票）。

## 交付切片（跨面但单点演示）
- **变更单 UI（接线既有工作台，纯增量）**：
  - 新建：父合同选择（非 superseded active 合同）、reason、逐字段变更输入（键取业务主体字段、金额转整数分）；走 `POST /api/amendments`。
  - 详情 + 新旧对照：消费 `GET /api/amendments/:id` 的 `field/from/to` 对照载荷，逐字段渲染「旧值 → 新值」。
  - 审批动作：按当前用户角色显隐 submit/approve/reject/apply（前端仅显隐，服务端仍强校验）；apply 后刷新合同列表（可见继任 v2、父被隐藏）。
  - 版本链提示：对继任合同显示 `version` 与 `parent_contract_id`。
- **相对方管理 UI**：列表（名称/信用代码/联系人/风险评级）、新建/编辑表单、删除；去重失败（409 DUPLICATE）展示「已存在」提示并回带既有实体；操作全走真实 API。
- **角色提示**：只读用户隐藏写按钮（服务端仍 403 兜底，前端不复算规则）。
- **接线冒烟（F-0005，作为本票唯一积分的挂载断言）**：静态页面可达（沿用既有挂载）；变更单详情 + 相对方管理页从真实 API 渲染；表单/审批/apply 走真实 API 并正确刷新。

## 验收条件（机械可判）
1. 冒烟：静态面可达；变更单列表/详情（含新旧对照）与相对方管理页均从真实 API 渲染。
2. 相对方管理：创建/编辑/删除往返；409 去重在 UI 呈现「重复」提示且不产生半态。
3. 变更单全流程（UI 驱动）：建 → 提交 → admin 批准 → apply → 合同列表继任 v2 可见、父被隐藏（默认）、`?include_superseded` 可见父。
4. 对照渲染：逐 changed 字段显示旧值 vs 新值（旧=父当前值、新=changes）。
5. 角色：viewer 不渲染写按钮，且服务端 403 兜底（越权场景断言）。
6. 全部既有测试仍绿（回归：合同面改动零破坏既有行为）。

## 演示/验证（S4）
`node --test` 全量 + 冒烟断言：静态可达、两域 UI 经真实 API 渲染、变更单全流程 UI 驱动、去重提示、角色兜底、既有测试无回归。
