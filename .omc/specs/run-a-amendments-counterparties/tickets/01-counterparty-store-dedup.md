# T1 相对方域：校验 + 去重 + 存储（seam S2）· ready-for-agent（C3 预授权）

`blockedBy: []` — 起点，无阻塞。与 T3（变更单域）文件面不相交，可并行。
目标：立起可判对错的相对方领域与存储基座，杜绝去重/校验只在 API 层临时拼。

## 交付切片（跨面但单点演示）
- **领域纯函数（新模块，契约新增）**：相对方字段校验（名称必填、统一社会信用代码必填且格式合法、联系人可选、风险评级 ∈ `D|C|B|A|R` 默认 `C`）；创建/更新返回新对象（不可变，不 mutate 入参）；「信用代码唯一」去重判定（全库扫描，命中 → 返回冲突与既有实体）；「重名再判」——仅名称同而信用代码不同 → 放行。
- **既有旧种子容错**：读取仅含 `id`+`name` 的旧行不抛错不写回，`contact: null`、`risk_rating` 回填 `C`，`credit_code` 置空串（旧行无码）。
- **存储接线**：以可替换 Storage（复用既有文件存储工厂）承载 `data/counterparties.json`，增删改查 + 整存整取 + 单例锁 + 原子写；Store 层不内联业务校验（领域纯函数单一事实源）。
- **ID**：沿用既有 `cp_` 前缀 id。

## 验收条件（机械可判）
1. 校验矩阵：缺名称/缺信用代码/非法评级/非法信用代码长度 → 拒绝；合法通过；风险缺省得 `C`。
2. 去重：与既有实体信用代码相同 → 拒绝并回带既有 id；同码+同名的"重名+同码"亦在此被拒；仅重名不同码 → 放行。
3. 不可变：create/update 返回新对象，入参数组/元素不被 mutate。
4. 旧种子行（仅 id+name）读取不抛、`risk_rating` 回填 `C`、`credit_code` 为空串。
5. store 往返：create/get/update/remove 一致；并发写（多路 read-modify-write）最终一致、无丢写；原子落盘可重启读回。
6. 金额/越权/非法跳转中与本票相关者：无（领域层相对方无金额状态机；越权与状态机在 S3/T2 覆盖）。
