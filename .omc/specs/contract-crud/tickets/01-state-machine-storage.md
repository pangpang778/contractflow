# T1 状态机 + 存储层（seam S1）· 候选 (待 C3 批准)

`blockedBy: []` — 起点，无阻塞。
目标：立起可判对错的领域与存储基座，让 T2/T3 站在其上。
状态：候选 —— 批准后标 `ready-for-agent`。

## 目标（contract = 契约，非坐标）
为合同的增删改查、生命周期迁移、金额整数语义提供纯函数领域层与可替换存储，全部行为由 `node --test` 断言。

## 交付切片（跨面但单点演示）
- **领域层**：合同字段集与校验（必填、金额整数分 ≥0、`currency:"CNY"`、日期 `YYYY-MM-DD` 且 start≤end）、状态机迁移矩阵（draft/in_review/pending_sign/active/archived/void/expired，白名单 + 终态无出边）、不可变迁移：迁移返回新版合同且不 mutate 原对象。
- **冻结**：`active` 后对业务主体字段（金额/币种/期限/相对方/标题）的更新被拒；状态字段不被外部回传覆盖。
- **存储**：可替换 Storage 接口；合同增删改查、整存整取、进程内单例锁 serialize read-modify-write、写临时文件 + 原子 rename；无数据文件时首写建目录/文件。
- **ID**：合同 `c_<epoch>-<rand>`、相对方 `cp_<...>`，前缀分域、生成后不可变、并发下唯一。

## 验收条件（机械可判）
1. 迁移矩阵对每一条合法边返回新版，对每一条非法边抛错且状态不变。
2. 终态（archived/void/expired）无迁移出边。
3. `active` 后进行冻结字段更新被拒；外部回传 status 不生效。
4. 金额校验拒浮点/负数/非整分；范围合法通过；一切以整数分运算。
5. 并发写（多路 read-modify-write）下最终一致、无丢写；单例锁生效。
6. 持久化以原子方式完成——中途失败不留半截文件；重启可读回。
7. ID 在并发批量生成下唯一。

## 演示/验证（S1）
运行 `node --test`：状态机矩阵、冻结语义、金额整数、CRUD 往返、并发原子写、ID 唯一性各一组用例通过。金额、非法状态跳转两类缺陷场景各 ≥1（process.md）。
