# T3 工作台 UI + 前端冒烟（seam S3 + 集成接线）· 候选 (待 C3 批准)

`blockedBy: [02-http-api-role]` — 需要真实 API 可消费。
目标：把 API 变成人可用的工作台，并完成静态服务接线这一本仓库首个「被挂载的切片」。
状态：候选 —— 批准后标 `ready-for-agent`。

## 交付切片（跨面且含集成接线；integration-wiring F-0005）
- **静态服务**：server 在同一端口托管静态面（vanilla HTML/CSS/JS），`/` 可达某入口页；`/api/*` 前缀不落入静态映射（路由分界）。
- **令牌落地**：从 design-system tokens 单一事实源导出 CSS `:root` 变量（最小生成器，`node:test` 可测；避免手写 CSS 造成双源漂移）；状态色只取 `color.status`。
- **工作台三面**：
  - 列表：从 `GET /api/contracts` 渲染（标题、相对方、金额以分转元显示、状态色点）。
  - 详情：从 `GET /api/contracts/:id` 渲染并展示只读/可编辑提示。
  - 新建表单：提交走 `POST /api/contracts`，遵守身份角色；错误信封渲染为可见错误，不静默。
- **挂载与冒烟**：入口 HTML 有明确挂载点，JS 挂载后从真实 API 拉数渲染（S3）。

## 验收条件（机械可判）
1. 静态页可达：`GET /` 返回入口 HTML 且含挂载点。
2. 列表/详情从真实 API 渲染（数据来自存储，非硬编码）。
3. 新建表单经 API 成功落盘并回显；非法输入渲染错误信封。
4. 状态色取自令牌且随状态变化可辨。
5. 前端不复制业务规则（不内置状态机矩阵/金额校验逻辑；校验交给服务端）。
6. 冒烟断言：静态可达 + 挂载渲染 + 表单走真实 API（S3）。

## 演示/验证（S3）
`node --test`：入口可达、挂载渲染、表单 round-trip 通过；server 同时托管 `/api` 与静态面为一处接线。
