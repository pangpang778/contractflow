# T2 HTTP API + 角色校验（seam S2）· 候选 (待 C3 批准)

`blockedBy: [01-state-machine-storage]` — 领域与存储就绪后接受真实请求。
目标：以临时端口启动真实 server，把 CRUD/迁移/角色拒绝/校验矩阵变为可测外部行为。
状态：候选 —— 批准后标 `ready-for-agent`。

## 交付切片（跨面但单点演示）
- **服务**：`node:http` 起服务；路由 `GET/POST /api/contracts`、`GET/PATCH/DELETE /api/contracts/:id`、`POST /api/contracts/:id/status`、`GET /api/counterparties`。
- **校验**：创建/更新走领域校验（复用 T1 契约），非法输入 400。
- **错误信封**：统一 `{ok,data,error}`；每路由兜底，不向客户端抛栈。
- **角色授权**：读 `X-User-Role`，缺失/非法 → 401 或 403；admin/editor/viewer 三档按 spec 权限矩阵强制；编辑/迁移在服务端再次校验冻结与白名单（不信前端回传）。
- **状态迁移端到端**：`POST /:id/status` 只接受 `to` 动作，委托领域迁移矩阵；合法改造状态、非法/越权拒绝。
- **相对方**：只读静态种子经 API 暴露；合同以 `counterparty_id` 引用。

## 验收条件（机械可判）
1. 三档角色对 spec 权限矩阵每一行至少一条用例全过（读取皆可；写按角色放行/403；审批/作废/到期/删除 admin-only）。
2. 身份头缺失或角色非法 → 401 或 403，绝不落入业务分支。
3. 金额/日期校验矩阵（US2 ①–④）在 HTTP 层各返回 400 且错误信封统一。
4. 迁移：合法边 200 改状态；非法边 409；越权 403；对冻结方试图改主体字段 409。
5. 写操作为不可变的整存整取落盘；错误路径不吞异常、不外泄栈。
6. 临时端口真实服务集成测试：金额、越权、非法状态跳转三类缺陷场景各 ≥1（process.md）。
