# T3 前端审批操作（seam S4）· 候选 (待 C3 批准)

`blockedBy: [02-approval-api-outbox]` — 需要 submit/approve/reject 真实 API 可消费。
目标：把审批能力变成人可用的工作台交互，并做本功能的前端接线 + 冒烟。
状态：候选 —— 批准后标 `ready-for-agent`。

## 交付切片（跨面但含接线；integration-wiring F-0005）
- **提交审批**：`draft` 合同的详情/列表提供「提交审批」入口 → `POST /:id/submit`；成功后展示生成的审批链（级别/所需角色）。
- **审批面板**：`in_review` 合同渲染链步骤卡片，逐级显示状态（待决/已通过/已驳回）与留痕（谁/何时/意见）；仅当调用者角色 == 当前待决步骤必需角色（且非提交人）时显示「通过」「驳回」按钮。
- **动作表单**：approve 走 `POST /:id/approve`，reject 走 `POST /:id/reject`，均含必填意见文本框；驳回原因（拒绝意见）在链上可见回显。
- **角色感知**：`X-User-Role`（含 legal）驱动按钮显隐；前端**不复制**金额分级/链状态机/当前步骤规则——链与当前步骤一律从服务端返回数据渲染（error 信封渲染为可见错误，不静默）。
- **冒烟断言**：静态可达 + 审批入口渲染 + approve/reject round-trip 走真实 API（S4）。

## 验收条件（机械可判）
1. US-A6①：静态面可达；列表/详情对带链的 `in_review` 合同渲染链与审批入口。
2. US-A6②：approve/reject 经真实 API 成功并留痕回显（approver/时点/意见可见）。
3. US-A6③：驳回原因（拒绝意见）在链上可见。
4. US-A6④：按角色隐去无权按钮（viewer / 非当前步骤角色 / 提交人看不到可点动作）。
5. US-A6⑤：前端不复制金额分级、链状态机、当前步骤判定（都取服务端数据）。
6. S4 冒烟：静态可达 + 挂载渲染 + 动作 round-trip 通过；error 信封渲染可见错误。

## 演示/验证（S4）
`node --test` 冒烟 + 手动：审批入口渲染、approve/reject 走真实 API、驳回意见回显、角色隐藏通过。
